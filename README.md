# Apple Support Retrieval and Routing Prototype

A Python demonstration of rule-based intent classification, escalation rules,
BM25 retrieval and selection of a stored support reply. This is an independent
portfolio project and is not affiliated with Apple.

## Implemented behavior

- Six intent categories and explicit escalation reasons.
- BM25 lexical retrieval over a small authored exemplar collection.
- Selection of an existing reply; no generative model is invoked.
- An offline development evaluation against two baselines and unit tests.
- A small standard-library HTTP demo, Dockerfile and Render configuration.

## Reproduce

```sh
python eval/reproduce_headline.py
python -m unittest discover -s tests
python server.py
```

## Evaluation integrity

`data/generate_data.py` authors templates and seed examples and expands these
into 200 synthetic development examples. Some examples reuse retrieval seeds.
They are not a held-out sample of Kaggle customer-support conversations.
No external customer dataset provenance is asserted by this repository.

`eval/judge.py` implements a deterministic **heuristic rubric**, not an LLM judge.
ROUGE-L measures token overlap, not semantic correctness or factual support.
There are no independently collected human labels or human/judge agreement
measurements. The earlier simulated human-calibration routine was removed.

The current measured results are in `reports/evaluation_results.json` and are
regenerated by the command above. They demonstrate behavior on these synthetic
fixtures only. Classification accuracy does not measure reply safety. No
production deployment quality, universal safety or latency guarantee is claimed.
